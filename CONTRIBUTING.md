# Como contribuir

Use o [guia de desenvolvimento](docs/DESENVOLVIMENTO.md) para preparar o ambiente.

1. Crie uma branch e mantenha a mudança focada no problema descrito.
2. Execute a suíte aplicável e informe o ambiente e os limites da validação.
3. Atualize a documentação quando o comportamento ou a instalação mudar.
4. Abra um pull request descrevendo o problema, o resultado e os testes.

Não adicione instaladores novos ao Git: os artefatos de distribuição pertencem
a Releases. Preserve as licenças do pypdf e das bibliotecas incluídas. Não
adicione arquivos pessoais, caches ou configurações locais de ferramentas.

Aprovação dos testes próprios não demonstra equivalência integral com outros
leitores. Diferencie comportamento implementado, teste executado e hipótese.
